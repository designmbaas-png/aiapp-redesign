# AiApp ETL 재생 엔진

> **Revive, don't rebuild.**
> 새로 만들지 말고, 되살리세요.

멈춘 웹사이트·앱을 **원본 그대로 보존한 채** 최신 스택으로 되살리는 AiApp의 핵심 기술, **시맨틱 ETL 재생 엔진(Semantic ETL Revival Engine)** 에 대한 설명 문서입니다.

*본 문서는 랜딩 페이지 카피 작성을 위한 원본 정리본입니다. 섹션 단위로 랜딩 블록에 대응하도록 구성했습니다.*

---

## 1. 한 줄 정의

**ETL 재생 엔진**은 이미 운영 중이거나 멈춰 있는 웹서비스를 **입력값으로 받아**, 그 안의 데이터·콘텐츠·브랜드를 해석하고 보존하면서 최신 기술 스택 위에 다시 세워 **즉시 운영 가능한 상태로 내보내는** 파이프라인입니다.

빈 화면에서 새로 만드는 것이 아니라, **있는 것을 읽어서 다시 살립니다.**

---

## 2. 왜 '재생'인가 — 문제 정의

소상공인에게 웹사이트·앱은 매출·예약·고객 신뢰가 지나가는 통로입니다. 그런데 대부분은 이걸 스스로 유지하지 못합니다.

| 상황 | 결과 |
|---|---|
| 제작 업체가 사라짐 | 수정할 사람이 없음 |
| 기술 스택 노후화 | 한 줄도 못 바꿈 |
| 서비스 멈춤·방치 | 매출·예약 유입 중단 |
| 복구 문의 | **수천만 원 규모의 "전면 재제작" 견적** |

문제는 기존 도구들도 같은 답을 준다는 점입니다.

> 기존 노코드·AI 빌더는 **빈 템플릿에서 새로 만들 뿐**, 이미 있는 사이트를 복구하지 않습니다.

즉 시장의 모든 선택지가 *"다시 만들어야 한다"* 는 전제를 공유합니다.
AiApp은 그 전제 자체를 바꿉니다 — **작업 단위를 '재제작(rebuild)'에서 '재생(revive)'으로 전환합니다.**

---

## 3. ETL이란 무엇인가 (기본 개념)

ETL은 데이터 엔지니어링의 표준 개념으로, 세 단계의 앞글자입니다.

| 단계 | 원어 | 의미 |
|---|---|---|
| **E** | Extract | 추출 — 원본에서 데이터를 뽑아냄 |
| **T** | Transform | 변환 — 새 시스템이 이해할 형태로 바꿈 |
| **L** | Load | 적재 — 새 시스템에 실어 넣음 |

AiApp의 ETL이 일반 ETL과 다른 지점은 **"시맨틱(Semantic, 의미 기반)"** 이라는 수식어입니다.
데이터 값만 옮기는 게 아니라, **코드가 무엇을 하려던 것인지(의도·문맥)까지 해석해서** 옮깁니다.

---

## 4. 3단계 동작 원리

### Extract — 살아 있는 화면을 데이터로 되돌리기

- 라이브 사이트의 **런타임 DOM/CSSOM** 캡처 → 실제 렌더된 결과를 구조 데이터로 확보
- **네트워크 호출** 추적 → 어떤 API·엔드포인트에 의존하고 있었는지 파악
- 위 두 정보를 역추적해 **데이터 스키마 복원**

> 원본 소스코드나 문서가 남아 있지 않아도, 브라우저에 그려진 결과물로부터 구조를 되돌립니다.

### Transform — 의미를 이해한 뒤 최신 스택으로 재구성

- **AST(추상 구문 트리) 분석** → 코드를 문법 구조 단위로 해부
- **LLM 시맨틱 추론** → 각 구조가 담당하던 비즈니스 로직·의도를 해석
- 원본의 **데이터·레이아웃·브랜드를 보존한 상태로** 최신 기술 스택 위에 로직 재구성

> 여기가 범용 템플릿 이식과 갈리는 지점입니다. 결과물은 "비슷한 사이트"가 아니라 **여전히 내 사이트**로 읽힙니다.

### Load — 관리형 백엔드에 프로비저닝, 즉시 운영

- 재구성된 서비스를 **관리형 백엔드에 자동 프로비저닝**
- 내장 BaaS로 **회원·결제·예약·문의**를 자동 연결
- 정적 페이지가 아니라, **처음부터 거래가 발생하는 상용 서비스**로 기동

---

## 5. 재생 이후 — 개발자 없이 운영

ETL 재생은 시작점일 뿐이고, 그 뒤 운영이 실제 가치입니다.

- **대화 한 줄 편집** — 콘텐츠·상품·공지를 자연어 요청으로 즉시 반영
- **버전 저장·롤백** — 모든 편집이 되돌릴 수 있어 자가 편집 부담이 낮음
- **기술 용어 없는 UI** — 설정 화면·메뉴 학습 없이 "말로 설명하면 적용됨"

---

## 6. 재생을 가능하게 하는 아키텍처

ETL 엔진은 단독으로 동작하지 않고, 두 개의 층과 함께 묶여 있습니다.

```
┌─────────────────────────────────────────────┐
│  ① 시맨틱 ETL 재생 엔진                        │
│     Extract → Transform → Load               │
├─────────────────────────────────────────────┤
│  ② 내장 BaaS                                  │
│     인증 · DB · 스토리지/CDN · 결제 · 메시지     │
├─────────────────────────────────────────────┤
│  ③ MCP 통합 Main–Sub 멀티에이전트                │
│     메인이 요청 분해 → 서브가 병렬 생성 → Self-Fix │
└─────────────────────────────────────────────┘
        서버리스 · 멀티 LLM · 다국어 · 단일 빌드
```

- **Main–Sub 멀티에이전트** — 메인 에이전트가 요청을 분해하고, 전문화된 서브 에이전트가 프론트엔드·백엔드·API·대시보드를 **병렬 생성**. 오류는 **Self-Fix 루프**가 감지→수정 반복
- **MCP(Model Context Protocol)** — AI가 외부 도구·데이터에 표준 방식으로 접속
- **서버리스** — 요청이 올 때만 실행 → 상시 서버 유휴 전력·비용 절감
- **단일 빌드 → 반응형 웹 · Android · iOS** 동시 출력

## 8. 경쟁 유형 대비 차별점

| | 템플릿 노코드·웹빌더 | AI 프롬프트→앱 생성기 | **AiApp** |
|---|---|---|---|
| 시작점 | 빈 캔버스 | 빈 프롬프트 | **기존 라이브 서비스** |
| 기존 서비스 진단 | ✕ | ✕ | **○ (작업 전 리포트)** |
| 원본 데이터·브랜드 보존 | ✕ | ✕ | **○** |
| 결과물 성격 | 새 사이트 | 정적 결과물 | **상용 운영 가능 서비스** |
| 결제·회원·예약 연결 | 별도 연동 | ✕ | **○ (내장 BaaS 자동)** |
| 생성 구조 | 수동 편집 | 단일 모델 | **MCP 멀티에이전트 병렬** |

**핵심:** 멈춘 서비스를 **입력으로 받아** 상용 운영 가능하게 되살리는 방식은 AiApp이 유일합니다.

## 9. 확장성

- 레거시 진단 결과가 **재사용 가능한 표준 스키마로 축적** → 사이트 유형별 커버리지가 누적 향상
- 동일 파이프라인이 **다국어·해외 배포**로 확장
- 현지 연동 레이어(소셜 로그인·PG 결제·메시지)는 **시장 단위로 추가**

## 부록 · 용어 사전

| 용어 | 원어 | 뜻 |
|---|---|---|
| ETL | Extract–Transform–Load | 추출–변환–적재 3단계. 재생 엔진의 핵심 |
| 시맨틱 ETL | Semantic ETL | 값만이 아니라 **의미·문맥까지** 해석해 옮기는 ETL |
| 재생 vs 재제작 | revive vs rebuild | 재생은 원본 보존 복구, 재제작은 빈 템플릿에서 새로 만들기 |
| DOM/CSSOM | Document/CSS Object Model | 문서·스타일 모델. 렌더된 화면을 데이터로 추출 |
| AST | Abstract Syntax Tree | 추상 구문 트리. 코드를 구조 단위로 분석 |
| BaaS | Backend as a Service | 인증·DB·스토리지·결제 등 서버 기능을 미리 제공 |
| 서버리스 | serverless | 요청 시에만 실행 → 유휴 전력·비용 절감 |
| Main–Sub 멀티에이전트 | Main–Sub multi-agent | 메인이 분해하고 서브가 병렬 처리 |
| Self-Fix | self-fix loop | 오류 감지→수정을 반복하는 자동 교정 루프 |
| MCP | Model Context Protocol | AI가 외부 도구·데이터에 접속하는 표준 프로토콜 |
| 프로비저닝 | provision | 인프라·자원의 자동 준비·배치 |
